# Doodh Hisaab 🥛

A daily ledger app for the Pakistani **doodh wala** (milkman). Record each
day's supply in under two minutes and generate an accurate monthly bill per
customer, with naga days clearly shown — so there's nothing left to argue
about at month end.

Built with **Flutter**, **offline-first** (local SQLite), Android-first, with
**Roman Urdu / English** labels.

> This repository implements the [Doodh Hisaab case study](https://claude.ai/artifact/CJh33DiVet3DxdwqeTsEi2):
> a milkman's daily ledger where **the default is "supplied"** and the doodh
> wala only taps the exceptions — naga, extra, khula and payment.

---

## The core idea

Everything is built around one principle from the case study:

> **If the doodh wala does nothing on a customer's card, it counts as normal
> supply.** The only taps in a day are **Naga**, **+ Extra**, **Khula** and
> **Payment**.

Each regular customer has a fixed daily order. On the Today screen the app
assumes that order is delivered unless told otherwise, so a normal 50-customer
round with 3 nagas and 1 extra is about **5 taps**.

## Features (MVP)

| Case-study requirement | Where it lives |
| --- | --- |
| Customer list with fixed daily order (qty, unit, rate, shift) | `Customers`, `Add/edit customer` |
| Daily route — mark naga / extra, close the round | `Aaj ka Route` (Today) |
| Naga per customer, optional reason, no charge | Today screen + naga reason sheet |
| Loose "Rs 100 ka" sales (walk-in or tied to a customer) | Floating **Khula** button |
| Payments (cash, JazzCash, Easypaisa, bank) | Payment sheet |
| Khata calendar: ✓ delivered, **N** naga, **+** extra | `Customer` detail |
| Rate history (Rs 210 till 14th, Rs 220 from 15th) | `rate` table, snapshotted per entry |
| Monthly bill, shareable on WhatsApp | `Monthly bill` screen |
| Daily & monthly totals, naga split by reason | `Hisaab` (Reports) |

## Screens

1. **Aaj ka Route (Today)** — customer cards with the fixed quantity
   pre-filled; big **Naga** and **+ Extra** buttons; sticky footer with the
   day's total; floating **Khula** button; **Round khatam** saves everything
   not marked naga as delivered.
2. **Customers** — searchable list with each person's running balance; tap to
   open their khata (a month calendar + payments + balance).
3. **Hisaab (Reports)** — today's and this month's sales, total naga (split
   into *customer away* vs *I missed*), total payments, total outstanding.
4. **Add / edit customer** — name, phone, house/shop, address note, route
   position, unit, fixed quantity per shift, rate, opening balance.
5. **Monthly bill** — one customer, one month: days supplied, naga dates,
   extras, rate(s), total, payments, balance due → **WhatsApp par bhejo** or
   share as an image.

## Getting started

### Prerequisites
- [Flutter SDK](https://docs.flutter.dev/get-started/install) 3.3 or newer
- Android Studio / Android SDK (for an Android build), or Xcode (for iOS)

### Run it

This repo contains the Dart source (`lib/`), tests, and project config. The
platform folders (`android/`, `ios/`, …) are generated by Flutter, so after
cloning, run **`flutter create .`** once — it fills in the missing platform
scaffolding **without touching `lib/` or `pubspec.yaml`**:

```bash
git clone https://github.com/abshah2005/Doodh-hisab.git
cd Doodh-hisab
flutter create .            # generates android/ios/… platform folders
flutter pub get
flutter run                 # on a connected device or emulator
```

To build a release APK for a real phone:

```bash
flutter build apk --release
# output: build/app/outputs/flutter-apk/app-release.apk
```

The app seeds a few demo customers on first launch so you can explore it
immediately.

### Run the tests

```bash
flutter test
```

`test/bill_calculator_test.dart` reproduces the worked example from the case
study (Rashid sahab: 27 days, 55 kg, Rs 220/kg, 3 nagas, Rs 500 previous
balance, Rs 10,000 paid → **Rs 2,600 due**) and checks naga handling and
mid-month rate changes.

## How the bill is calculated

For each customer and date range (section 8 of the case study):

- **Milk charges** = Σ over delivered + extra entries of `quantity × rate on
  that date`. The rate is snapshotted onto each entry when it is recorded, so
  historical bills stay stable even after a rate change.
- **Naga days** = count of naga entries (shown with dates, charged zero).
- **Balance due** = previous balance + milk charges − payments in the period,
  where previous balance = opening balance + prior milk − prior payments.

A `DailyEntry` is stored for every customer on every closed shift. It costs
almost nothing in storage and makes a bill a simple sum over rows instead of
"fixed order minus nagas plus extras," which gets messy when orders and rates
change mid-month.

## Project structure

```
lib/
├── main.dart                      # bootstraps the DB + settings, runs the app
├── app.dart                       # MaterialApp + theme
├── theme.dart                     # milk-and-ink theme, big touch targets
├── l10n/strings.dart              # bilingual (Roman Urdu / English) labels
├── util/                          # date + number/currency formatting
├── state/settings_controller.dart # language, two-rounds, business name
├── data/
│   ├── enums.dart                 # CustomerType, MilkUnit, Shift, EntryStatus…
│   ├── app_database.dart          # SQLite schema + first-run seed data
│   ├── models/                    # Customer, FixedOrder, Rate, DailyEntry,
│   │                              #   LooseSale, Payment
│   └── repositories/              # customer, entry, payment, rate, billing,
│                                  #   settings
├── services/
│   ├── bill.dart                  # pure bill-calculation logic (tested)
│   └── bill_message.dart          # Roman Urdu WhatsApp summary
├── widgets/                       # customer card + bottom sheets
└── screens/                       # the 5 screens + settings + customer detail
```

## Data model

`customer`, `fixed_order`, `rate`, `daily_entry`, `loose_sale`, `payment`,
`setting` — small enough for on-device SQLite. See
`lib/data/app_database.dart` for the schema.
